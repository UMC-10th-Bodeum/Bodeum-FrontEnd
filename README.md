## 🤝 Convention & Collaboration

### Branch Convention

```text
type/#이슈번호-description
```

| Type     | Description                       |
| -------- | --------------------------------- |
| feat     | 새로운 기능 개발                  |
| fix      | 버그 수정                         |
| hotfix   | 긴급 수정                         |
| refactor | 리팩토링                          |
| design   | UI 작업                           |
| style    | 코드 스타일 수정 (기능 변경 없음) |
| docs     | 문서 수정                         |
| chore    | 프로젝트 설정 및 패키지 관리      |
| test     | 테스트 코드 작성                  |

### Commit Convention

```text
type: 내용
```

| Type     | Description      |
| -------- | ---------------- |
| feat     | 새로운 기능 추가 |
| fix      | 버그 수정        |
| refactor | 리팩토링         |
| style    | 코드 스타일 수정 |
| docs     | 문서 수정        |
| test     | 테스트 코드      |
| chore    | 설정 변경        |
| build    | 빌드 관련        |
| ci       | CI/CD            |
| perf     | 성능 개선        |

### PR Convention

```text
[Type] 내용
```

PR은 `.github/PULL_REQUEST_TEMPLATE.md` 템플릿을 기준으로 작성합니다.

- 작업 내용: 구현하거나 수정한 내용을 요약합니다.
- 스크린샷: UI 변경이 있는 경우 화면을 첨부합니다.
- 체크리스트: 리뷰 전 확인한 내용을 체크합니다.
- 참고 사항: 리뷰어가 알아야 할 내용을 작성합니다.
- 관련 이슈: `Closes #이슈번호` 형식으로 연결합니다.

### 협업 규칙

- 하나의 브랜치에서는 하나의 기능만 개발하는 것을 권장합니다.

- 1명 이상의 리뷰 승인 후 `dev`에 Merge합니다.
- 반드시 `dev` 브랜치에 merge합니다. (`main` 에 바로 merge하지 않습니다.)
